# Prompt — Destination Deck / Parceria

> Usar para montar um deck de destino (uso interno ou para apresentar a uma marca/parceiro em potencial), a partir de um `content/destination-brief-template.md` preenchido.

```text
Monte um deck de destino para [nome do destino], a partir do brief preenchido anexado.

Estrutura do deck:
1. Capa — nome do destino, gancho visual (Editorial Escape, ver social/carousel-system.md)
2. Por que esse destino / por que agora — 1 slide de contexto
3. O que vale — 1 slide (template "vale ou não vale")
4. O que evitar — mesmo slide ou complementar
5. Roteiro/rota sugerida — 1 slide (template "roteiro/mapa funcional"), só com dados reais confirmados
6. Informação prática (preço/documentação) — sempre com fonte e data ou [VERIFICAR FONTE E DATA]
7. Para quem é / para quem não é — 1 slide
8. Se for deck de parceria: seção de proposta de colaboração — formatos possíveis (ugc/deliverables-matrix.md),
   com disclosure e limites claros (ugc/disclosure-rules.md, content/review-integrity-rules.md)
9. Fechamento com CTA claro

Regras:
- Nenhum dado de preço, disponibilidade ou parceria deve ser apresentado como confirmado sem fonte e data reais.
- Não inserir logo de marca/hotel sugerindo parceria que não foi confirmada por escrito.
- Manter a paleta e tipografia do sistema (tokens/tokens.json) — nenhuma cor ou fonte fora do sistema.
- Se o deck é para uso externo (apresentação a marca), marcar claramente quais dados são reais e quais são
  placeholder de exemplo.
```
